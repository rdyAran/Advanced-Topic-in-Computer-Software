# 04 · FloodLink NLP Model (model card)

## หน้าที่

อ่านข้อความขอความช่วยเหลือภาษาไทย 1 ข้อความ แล้วตอบ:

- **ประเภทข้อความ** (5 คลาส): help_request · hazard_report · status_update_resolved · donation_offer · irrelevant
- **ระดับน้ำ** (7 คลาส): none · knee · waist · chest · floor1 · floor2 · roof
- **กลุ่มเปราะบาง** (multi-label 7): bedridden · dialysis · heart · pregnant · injured · disabled_blind · wheelchair
- **สิ่งที่ต้องการ** (multi-label 6): food · water · milk · medicine · evacuation · power
- **ค่าตัวเลข/ข้อความ** (`entities.py`): จำนวนผู้ใหญ่, อายุเด็ก/ผู้สูงอายุ (อ่านตัวเลขที่เขียนเป็นคำได้ เช่น "แปดสิบห้า" = 85), จำนวนวันที่ติดค้าง, เบอร์โทร, บ้านเลขที่, ซอย
- **ความมั่นใจ** ของแต่ละการตัดสินใจ: Agent (03) ใช้ตัดสินว่าต้องส่งต่อให้ LLM หรือไม่

## v1.1 (ใช้งานอยู่)

| | |
|---|---|
| Features | character n-gram (1–4) TF-IDF **และ concept tag จาก `lexicon.py`** (คำพ้องความหมายทางการแพทย์/น้ำท่วม และคำปฏิเสธ เช่น `NEG_FOOD`) |
| Heads | Logistic Regression: type · water · flags (one-vs-rest) · needs (one-vs-rest) |
| กฎความปลอดภัย | `help_bias=0.3`: ถ้า P(help_request) ≥ 0.3 ให้ถือเป็นคำขอความช่วยเหลือ · milk ต้องมีคำว่านมจริง (ไม่ใช่ "นม" ที่อยู่ใน "กินมา") |
| ข้อมูล | 8,000 ข้อความจาก `generate_data.py` v2 (ประกาศเตือนภัย/ปิดเคส/บริจาค/คอมเมนต์สร้างจากการประกอบชิ้นส่วน, มีคำปฏิเสธ, ข้อความแจ้งแทน) |
| เวลาเทรน / ความเร็ว | ~10 วินาที / ~5 ms ต่อข้อความ |
| hard set | ประเภทข้อความถูก 93% · needs F1 0.93 · ให้สีถูก 63% · จับเคสแดง 56% |
| จุดอ่อน | คำเรียกกลุ่มเปราะบางที่ไม่อยู่ในคลังคำ และโมเดล**มั่นใจสูงทั้งที่ผิด** ในกรณีนี้ → Agent (03) มีตัวกันที่ส่งต่อ LLM เมื่อเจอคำเกี่ยวกับสุขภาพแต่ไม่พบกลุ่มเปราะบาง |

**กับดักภาษาไทยที่เจอ:** ภาษาไทยไม่เว้นวรรค คำสั้นจึงซ่อนอยู่ในคำอื่นได้ ต้องเขียนคำในคลังให้เจาะจง:

| คำสั้น | ซ่อนอยู่ใน | ผล |
|---|---|---|
| "นม" | "กินมา", "ขึ้นมา" | จับผิดว่าต้องการนม |
| "อก" | "ออก" | จับผิดว่าน้ำถึงอก |
| "คอ" | "คอหงส์" | จับผิดว่าน้ำถึงคอ |
| "ยา" | "ยาย", "โรงพยาบาล" | จับผิดว่าต้องการยา |
| "เรือ" | "บ้านเรือน" | จับผิดว่าขอเรือ |
| "มีรถ" | "ไม่มีรถ" | จับผิดว่าเป็นข้อเสนอบริจาค |
| "คลอดแล้ว" | "ใกล้คลอดแล้ว" | จับผิดว่าเคสปิดแล้ว |

## v1 (ก่อนหน้า)

char n-gram อย่างเดียว ข้อมูล 3,000 ข้อความ · hard set: ประเภทข้อความถูก 80% · ให้สีถูก 63% · จับเคสแดง 67% · needs F1 0.71

## ปรับปรุงโมเดล

1. **ข้อมูลภาษาธรรมชาติ:** รัน `python generate_data_gemini.py --n 300 --per 3` (Gemini เขียนข้อความตาม label ที่เรากำหนด) **สุ่มตรวจด้วยตาก่อนนำไปเทรน**
2. **Distillation:** ทุกข้อความที่ Agent ส่งต่อ Gemini จะถูกบันทึกลง `data/teacher_labels.jsonl` แล้วนำมาเทรนต่อด้วย `python train.py --extra data/teacher_labels.jsonl data/gemini_train.jsonl`
3. **v2 (ข้อมูลจริง):** `train_wangchanberta_colab.ipynb` เทรน WangchanBERTa บน Google Colab ด้วยข้อมูลจริงจาก `realdata/`
   - โค้ดโมเดลอยู่ใน `floodwcb.py` (ไฟล์เดียวกันทั้งใน notebook และ backend) มี 6 หัวทำนาย ได้แก่ ประเภทข้อความ, กลุ่มเปราะบาง 11 แบบ, สิ่งที่ต้องการ, ระดับน้ำ, ติดต่อไม่ได้/ข้อมูลไม่พอ, และสี
   - สีสุดท้ายเลือกจากทางที่เร่งด่วนกว่า ระหว่าง "กฎ ปภ. จากข้อมูลที่ทาย" กับ "หัวทำนายสี"
   - เกณฑ์ของกลุ่มอันตรายถึงชีวิตตั้งจากชุด dev ให้จับเคสแดงได้ ≥98% ถ้าประเภทข้อความทายผิดแต่มีสัญญาณอันตรายชัด จะถือเป็นเคสขอความช่วยเหลือไว้ก่อน
   - แก้ `floodwcb.py` แล้วรัน `python make_notebook.py` เพื่อสร้าง notebook ใหม่
   - `train_wangchanberta.py` (ข้อมูลจำลอง) ถูกแทนที่ด้วย notebook นี้แล้ว
4. ระหว่างปรับให้ดูผลจาก**ชุด dev** (`error_analysis.py`) และใช้ชุด hard วัดตอนจบเท่านั้น จากนั้นรัน `python ../05_evaluation/evaluate.py --compare` แล้วบันทึกผลลง README หลัก
5. เพิ่มคำพ้องลงใน `floodnlp/lexicon.py` ได้เรื่อย ๆ แต่ระวังคำสั้นที่ซ่อนอยู่ในคำอื่น (ดูตารางข้างบน)
